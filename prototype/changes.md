# Prototype changes

Every change made during the prototype phase, newest at the bottom. Design decisions before 2026-10-06 are in `wireframes/decisions.md` (D1–D62). Screen numbers are from `screens.md`.

| Date | Screen | Change |
|---|---|---|
| 2026-10-06 | Header (all pages with a back button) | The arrow and the page title form one back button, with a hit area that reaches past the text. The gap between the arrow and the title grew from 8px to 14px. Pressing it gives a light grey background. |
| 2026-10-06 | (process) | Forward-only working mode: the prototype is the source of truth and `wireframes/` is frozen. `screens.md` is the screen map. The unnumbered screens were given numbers: 4.2. Delete Period and 6.1. Edit Setting. |
| 2026-10-06 | 5.2. Goals | Stronger goal colors. The icon tiles in the goal list now use the goal's own color (chosen in 5.6) at about 33% strength instead of the pale tint. The Sinh hoạt card uses the full pale tint as its background, and its border and bar outline use the color at 50%. The other screens keep the pale tiles. |
| 2026-10-06 | 5.2. Goals | Still too pale, so the colors are stronger again. Goal icon tiles are filled with the goal's full color. The Sinh hoạt card background is its color at 25%, and the border and bar outline use the full color. |
| 2026-10-06 | 5.2. Goals | Reverted the previous row. The 33% icon tiles and the Sinh hoạt card from the first change are back. |
| 2026-10-06 | 5.3. Statistics | In the Mục tiêu chart, the ring segments and legend dots now use each goal's full color instead of the pale tint. |
| 2026-10-06 | 4.0. Periods | The period cards were cramped. There is now a 5px gap between the name, the dates and the totals line, and the card padding is 12px (was 9px) top and bottom, 14px on the sides. Only 4.0 changes (class `mcard period`); the cards on 3.0 and 7.0 are unchanged. |
| 2026-10-06 | 5.3. Statistics | Swiping between charts no longer shrinks the bottom bar or shows a scrollbar. The slide-in animation started 28px outside the column, so for a moment the page was wider than the screen and the browser zoomed out. The app column now clips horizontal overflow (`.app { overflow-x: clip }`). This also covers the 5.0 tab and page slide-ins, which use the same animation. |
| 2026-10-06 | All screens | Data is no longer saved. It lives in memory only, so a page refresh resets the app to 1.0 Welcome. The zustand `persist` wrapper is removed, and on load the old saved copy (localStorage key `so-chi-tieu`) is deleted. |
| 2026-10-06 | All screens | Every page load now starts with the sample data (`demoData()` in `store/seed.ts`), so testers can tour the prototype right away. A refresh throws away any edits and brings the sample back. `?seed=empty` starts with no data and opens 1.0 Welcome; `?seed=demo` still works but is now the default. |
| 2026-10-06 | (deploy) | Docker test build for testers: image `expense-tracker-prototype` (tag `latest`, nginx serving the static build). `docker compose` in `prototype/`, host port from `.env` `HOST_PORT` (default 8080). `index.html` is sent no-cache so testers always get the latest build; hashed `/assets/` are cached for a year. App behavior is unchanged: sample data on every load. |
| 2026-10-06 | All pages | Going back to a page (e.g. 5.2 → ⚙ 6.0 → back) no longer makes its text large and teal. The page wrapper got the class `back` for the slide-from-left animation, which also matched the back-arrow style `.back` (26px teal), so the whole page inherited it. The direction classes are now `route-fwd` / `route-back`. |
| 2026-10-06 | 5.0. Period Detail | The back arrow now returns to the page you came from (4.0, 3.0 or 7.0) instead of always going to 4.0. When 5.0 is the first page opened (refresh or a direct link, so there is no earlier page in the app), it still goes to 4.0. |
| 2026-10-06 | All pop-ups (4.1, 5.4, 5.6, 5.9, 5.10, 6.1, 7.0 Số dư ban đầu) | Pressing Enter (the keyboard's Done/Go key) in a text or amount field now presses the pop-up's main button (Lưu / Tạo kỳ), if it is enabled; in 5.4 and 5.9 that is Lưu, not "Lưu & thêm tiếp". Date and dropdown fields are left alone. The amount and text fields set `enterKeyHint="done"` so the key shows as Done. On iPhone the number keypad has no Enter key at all, so amount fields there still need the Lưu button. |
| 2026-10-06 | (deploy) | Added `build_and_push.py`: double-click it to run `docker-compose build` and then, only if the build succeeds, `docker-compose push` to Docker Hub. The window stays open at the end so you can read the result. |
| 2026-10-07 | (deploy) | Installable web app (PWA, D55) via `vite-plugin-pwa`. The manifest is "Sổ chi tiêu", full screen (`standalone`), portrait, teal theme. The app icon is a white ₫ on teal (`app/public/icon.svg`). `npm run icons` regenerates the PNGs, and the Android maskable and iPhone icons get a teal background (`pwa-assets.config.ts`). The service worker precaches every built file, so the installed app opens offline. The Be Vietnam Pro font is now bundled (`@fontsource`) instead of loaded from Google Fonts, so it works offline and the app makes no outside requests. Updates: a new deploy downloads in the background and runs on the next launch, with no prompt and no reload mid-use. Install needs HTTPS. Data behavior is unchanged: every launch starts with the sample data and nothing is saved. |
| 2026-10-07 | (deploy) | `manifest.webmanifest` is now sent as `application/manifest+json`, with no-cache (`deploy/nginx.conf`). The nginx image's `mime.types` has no `.webmanifest` entry, so it was sent as `application/octet-stream`. Desktop Chrome installed the app anyway; the fix rules this out on phones. |
| 2026-10-08 | 5.0. Period Detail (Còn lại) | Dự trữ (goal reserve, R4) is now counted **per goal**: Σ max(target − spent, 0) over goals not done, instead of max(Σ targets − Σ spent, 0). Overspending one goal no longer lowers what the other goals still need, so Còn lại no longer shows that money as free. Sample Tháng 9: Nhà ở is 100 over, so the reserve is 500 (was 400) and Còn lại 10.000 (was 10.100). `domain/calc.ts` `reserve()`. |
| 2026-10-08 | 5.0. Period Detail (past periods) | Only the active period (R7.1, the newest start date) can be changed. In any other period: no ＋ button on any tab, no "Gửi tiết kiệm" button on 5.1 Thu nhập, and expenses, incomes, savings entries, Sinh hoạt and goals can't be tapped (CSS `.ro`). The 5.1 toggle, the 5.3 charts and the ⋯ menu (Sửa kỳ / Xóa kỳ) still work. Side effects: a period created with an older start date than the active one is read-only right away; giving a past period a newer start date in Sửa kỳ makes it the active one again. Kept until further design feedback. |
| 2026-10-08 | 3.0. Overview (Tổng tài sản shares) | The two percentages are now kept between 1% and 99%. Before, a very small part rounded to "0%" even though the bar is only shown when both parts are > 0 (e.g. 1 and 1.000 showed 0% · 100%, now 1% · 99%). `domain/calc.ts` `shares()`. |
| 2026-10-08 | 5.10. Savings Transfer | Withdrawals (Rút tiết kiệm) now use the same check as deposits: saving is allowed if the fund afterwards is ≥ 0, or not lower than it is now. Only matters when the fund is below 0 (after Số dư ban đầu is lowered or deleted, R6.7): lowering an existing withdrawal used to be blocked with "Vượt quá quỹ tiết kiệm" even though deleting it was allowed; any change that raises the fund is now allowed. A new withdrawal still can't overdraw the fund. `domain/calc.ts` `transferAllowed()`. |
| 2026-10-08 | 4.1. Create Period | No end date field any more: a period stays open (logging continues for as long as the user wants, a month or a quarter) until the next period is created. **Ngày bắt đầu** defaults to today and can't be earlier than today (nor the active period's start, if that is later); an earlier date shows "Không được trước hôm nay". This also applies to the very first period. The "Chọn kỳ trước đó" dropdown is removed: the carry-over (R1.8) always comes from the active period, shown as the "↩️ Còn lại từ tháng trước" line; with no periods yet there is none. `domain/periods.ts` `minNewStart()`, `createPeriod()`. |
| 2026-10-08 | 4.3. Close Period (new) | Tapping Tạo kỳ in 4.1 while an active period exists opens the dialog **Đóng kỳ “…”?** (Hủy / Tạo kỳ). Tạo kỳ closes the active period and creates the new one; Hủy returns to the filled form. Closing sets the old period's end date to the day before the new start, but never earlier than its last entry or its own start (`closingEnd()`); it then becomes read-only history. |
| 2026-10-08 | 4.1. Edit Period / 5.0 ⋯ | Sửa kỳ only exists for the active period (removed from ⋯ on past periods, which can't be edited at all; Xóa kỳ stays). It edits the name and the start date only; the start can't be earlier than the day after the previous period ends (`minEditStart()`), so the active period stays the newest (R7.1), and not after its first entry. |
| 2026-10-08 | 4.2. Delete Period | Deleting the active period makes the period before it active again (R7.1 already did this) and now also **reopens** it: its end date is cleared, so logging continues there. Undo restores both. Deleting a past period changes nothing else. `deletePeriod()`. |
| 2026-10-08 | 4.1. Create / Edit Period | Start dates are free again: no "Không được trước hôm nay" limit (when creating) or limit at the previous period's end (when editing), so a new user can start the first period on the 1st of the month and type in what they already logged elsewhere. 4.3 only appears when the new period would become the active one (start ≥ the active start); a start before the active period creates a past (read-only) period and closes nothing. After every create, edit or delete, `normalizePeriods()` keeps the periods consistent: the active period (newest start, R7.1) has no end, and any other period still open is closed the day before the next newer period starts (never before its last entry). A wrong date is fixed by re-dating: if an edit makes an older period active, it is reopened and the edited one closed; setting the date back flips it back. Editing still refuses a start after the period's first entry. |
| 2026-10-08 | 4.0. Periods, 3.0. Overview (period tile) | The period tile icon is now a drawn calendar (SVG, `CalendarIcon` in `components/ui.tsx`) in the tile's text color: dark teal on the light tile, white on the solid teal tile of the active period. The 🗓 emoji had fixed light colors and almost disappeared, worst on the active period. Every period shows the calendar: the optional per-period icon (only the sample "Du lịch Đà Lạt" had one, ✈️, and no screen could set it) is removed from the data. |
| 2026-10-08 | 1.1. Your Name (new), 2.0. Home, 2.1. Edit Name (new) | The data now stores a display name (`userName`, null at first). Whenever there is data but no name (the first start, after 1.0 Bắt đầu mới), 1.1 asks **Xin chào! Bạn tên gì?** with a name field and **Tiếp tục**, disabled while the field is empty; every other page redirects there until a name is set. 2.0's header now reads **Xin chào, {name} 👋** with a pencil button right after the name; it opens 2.1 **Đổi tên** (field prefilled, Lưu). Saving an empty name changes nothing and the old name stays. Names are trimmed and cut to 30 characters (`cleanName()` in `domain/types.ts`); a long name is shortened with … in the header so the pencil stays visible. The sample data's name is the fictional "Lan"; `?seed=empty` shows 1.1 after 1.0. |
